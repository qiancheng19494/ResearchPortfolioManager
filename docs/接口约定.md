# V1.3 内部接口约定

本轮保持现有服务接口、SQLite schema 1 和备份格式 1。

## 存储和配置

`database.store.Store(data_dir)` 暴露 `root`、`db_path`、`config`、`write_lock`。连接为独立 sqlite3 Row 连接，启用外键，每次调用自行关闭，不跨线程复用。写服务使用锁与事务。`save_config(dict)` 校验后原子保存。

`validate_config(values, defaults=None)` 合并默认值后要求 `name` 非空字符串，`background/interests` 字符串，`demo` 布尔值；错误指出字段，不强制转换错误类型。默认模板、读取、保存、备份和恢复共用。

`save_config` 校验后创建同目录独占随机临时文件，写入并 flush/fsync 后原子替换，成功才更新内存；失败保留旧文件与内存，只清理本次临时文件，不复用固定 `settings.tmp`。

## 项目、任务与成果

`services.portfolio.PortfolioService(store)`：

- `save_project(data, project_id=None) -> int`；`get_project(id)`；`list_projects(keyword='', category='', status='', include_archived=False)`；`archive_project(id, archived=True)`。
- `save_task(data, task_id=None) -> int`；`get_task(id)`；`list_tasks(keyword='', project_id=None, status='', active_only=False, due_filter='', today=None)`；`delete_task(id)`。
- `save_achievement(data, achievement_id=None) -> int`；`get_achievement(id)`；`list_achievements(keyword='', project_id=None, type='', status='', date_from='', date_to='')`；`delete_achievement(id)`。
- `dashboard(today=None)` 返回统计、今天/未来七天/逾期任务及最近项目；`project_detail(id)` 返回项目、任务、成果与材料。
- `require_project(id, writable=False)` 在写模式拒绝归档项目。

项目 `leader` 显式空串、空白、None 或非文本拒绝，字段未提供时才取已验证配置姓名。`due_filter` 为空代表普通列表，`today/overdue/upcoming` 分别为今天/逾期/明日至第七天，非法值拒绝。`task_due_groups(tasks, today=None)` 与概览共用边界，排除已完成、归档和空日期。`today` 可用固定参考日期测试。

日期为 ISO 日期字符串，空日期存 NULL；时间为本地 ISO 秒。列表返回字典，关联列表额外提供项目名称/归档标记，材料另提供成果名称。业务错误使用 ValueError 或明确异常。枚举来自 `PROJECT_CATEGORIES/PROJECT_STATUSES/TASK_STATUSES/TASK_DUE_FILTERS/PRIORITIES/ACHIEVEMENT_STATUSES`。

## 材料

`services.materials.MaterialService(store)`：

- `import_file(source, project_id, achievement_id=None, category='其他', version_label='V1', notes='') -> str`，返回 UUID。
- `list_materials(keyword='', project_id=None, achievement_id=None, category='')`；`get_material(id)`。
- `file_path(id, verify=False) -> Path`，不存在明确报错，verify 校验。
- `update_material(id, achievement_id=None, category='其他', version_label='V1', notes='')`，不能改项目或正式文件。
- `prepare_preview(material_id) -> Path`，后台核对原件并生成独立预览，再由主线程打开返回路径或父目录。
- `audit_materials() -> dict`，后台只读检查全部材料（含归档），返回 `checked_at/total/passed/failed/items`，单项异常不阻断其余材料。

材料记录含 UUID、项目/可空成果、原名、类别、版本、备注、大小、SHA-256、导入时间、相对路径。已暴露预览不自动清理，正式路径不传给关联程序，预览不入备份。

类别与版本标签须为去空白后非空字符串，备注须为字符串。`safe_relative_path(root, relative, materials_only=False)` 拒绝非规范路径、Windows 设备名和尾点/尾空格等名称，并检查已存在组件的重解析点/符号链接及硬链接文件。检查不得通过更新旧记录大小或 SHA-256 掩盖异常。

体检 `items` 提供材料标识、原名、项目、版本、相对路径、归档标记、预期/实际大小与 SHA-256，以及 `status/reason`。状态为 `passed/missing/changed/unsafe_path/error`；未能读取的实际值保留空值。结果对应本次读取期间，不自动修复。

## 导出、备份与界面

`services.export_backup.ExportBackupService(store)` 提供 `export_csv(destination, project_id=None, type='', status='')`、`export_html(destination, project_id)`、`backup(destination)`、`restore(archive, target)`，返回 Path，耗时操作在后台运行。恢复仅允许新建/空目录，不切换当前运行目录。

`export_integrity_report(destination, report) -> Path` 将完成的体检结果保存为 UTF-8 JSON。与其他导出共用 `_destination`，将目标和各受保护目录解析为实际路径再比较；JSON 使用独立临时文件并在完成后替换。界面新导出先清除旧成功结果，失败不调用成功回调。`MaterialIntegrityDialog` 展示后台返回报告，报告导出完成后由主线程更新状态。

`app.date_field.NullableDateField` 提供 `text/setText/clear/setReadOnly/isReadOnly/setPlaceholderText`，转发 `textChanged(str)` 与 `returnPressed`。`DateSelectionDialog` 显式确认后回填。

`runtime_paths.default_data_dir()` 区分源码/冻结程序；`restore_launch_command(data_dir)` 为当前实际运行环境生成 PowerShell 命令。主入口负责应用、进程锁和日志；`MainWindow(store)` 组织六页与后台任务。配置 `demo: true` 触发演示标记。默认姓名、背景和兴趣为可编辑的通用示例，不批量改写历史配置。
