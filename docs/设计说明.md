# V1.0 设计说明

记录日期：2026-10-10。名称：本科科研项目与成果档案管理系统 V1.0；内部名：ResearchPortfolioManager。

## 范围与模块

单用户、本地桌面、六个页面，不引入账号权限、云同步、经费审批、OCR、模型训练、自动查验成果或后台提醒。主窗口左侧导航、顶部标题、右侧内容、底部状态栏。个人资料、设置、关于使用弹窗。

| 路径 | 职责 |
| --- | --- |
| `main.py` | 参数、QApplication、数据目录进程锁、日志和启动错误 |
| `app/main_window.py` | 主窗口、导航、后台作业与统一刷新 |
| `app/pages.py` | 六个页面、筛选列表、按钮和详情入口 |
| `app/dialogs.py` | 项目、任务、成果、材料元数据及个人资料表单 |
| `app/workers.py` | 耗时操作的 Qt 后台线程封装 |
| `database/store.py` | schema 初始化、版本、独立连接、事务、配置保存 |
| `services/portfolio.py` | 项目、任务、成果、提醒与业务校验 |
| `services/materials.py` | 材料复制、哈希、相对路径与成果关联 |
| `services/export_backup.py` | CSV/HTML 导出、SQLite 快照、ZIP 与恢复验证 |
| `demo.py` | 拒绝非空目录的独立演示资料生成 |
| `tests/` | 临时资料目录的核心、完整流程及实际 GUI 测试 |

## 数据结构和约束

SQLite schema 版本为 1。每次服务调用开启并关闭独立连接，启用外键约束；不跨线程共享连接。写操作使用同一 Store 的可重入锁，数据库修改使用事务。SQL 值参数化；表名等内部固定标识来自代码。

Reviewed 修订不改变建表语句、索引、触发器或 schema 版本，不重建数据库。负责人修复置于表单与服务层，配置校验置于共用函数；恢复仍执行原有严格结构校验，不放宽全部规则。历史空负责人记录不自动补写，保留进入编辑并由本人填写的通路。

| 表 | 字段与用途 |
| --- | --- |
| `schema_info` | 唯一 schema 版本 |
| `projects` | ID、名称、类别、简介、负责人、起止日期、状态、备注、归档标志、创建与更新时间 |
| `tasks` | ID、必需项目 ID、标题、说明、可空截止日期、优先级、状态、完成时间、创建与更新时间 |
| `achievements` | ID、必需项目 ID、名称、类型、兼容状态、相关日期、编号/链接、贡献、备注、创建与更新时间 |
| `materials` | UUID、必需项目 ID、可空成果 ID、原文件名、类别、版本、备注、大小、SHA-256、导入时间、受管理相对路径 |

项目一对多关联任务、成果和材料。材料的 `(achievement_id, project_id)` 复合外键确保关联成果属于同一项目。删除成果遇到关联材料会被拒绝；先解除材料成果关联，材料本身保留。本版不物理删除项目或材料。归档是独立标志，归档项目及相关记录只读，服务校验和数据库触发器同时保护。

日期为 `YYYY-MM-DD`，空日期为 NULL；时间为本地 ISO 秒。业务校验合法日期、起止关系和必填项。数据库 CHECK 限制枚举、成果类型/状态组合、完成时间、大小及哈希长度。索引对应项目归档/类别/状态、任务项目/状态/截止日期、成果项目/类型/状态/日期以及材料项目/成果/类别。

负责人在新建和编辑服务中均要求字符串且去空白后非空，显式 `None` 不转换为文字。仅在数据中未提供 `leader` 字段时使用配置里已校验的 `name` 默认值。

`database/store.py:validate_config` 合并默认值后统一校验 `name/background/interests/demo`；默认模板、现有配置读取、设置保存、备份和恢复共用该规则。`name` 要求非空字符串，背景和兴趣要求字符串，演示标记要求布尔值；类型错误不自动转换、不覆盖原文件。读取与恢复的缺省字段仅在内存补全，不强制改写文件；实际保存继续使用临时文件原子替换。

## 提醒规则

以电脑本地日期为今天，内部 `dashboard(today)` 可接收固定日期。未完成且未归档项目的任务才进入提醒：截止早于今天为逾期，今天到期单独列出，明日至第七天为未来七天。空日期、已完成和归档项目任务不进入提醒。成果和材料总数包含仍保存的归档记录。

## 材料存储与补偿

白名单允许常见文档、图片、ZIP 等，拒绝脚本与可执行扩展名。只使用系统默认关联程序打开已允许文件，不执行脚本或 ZIP 内容。

导入先校验项目/成果，创建新的 UUID 目录，计算源文件 SHA-256，复制到 `.import.part`，核对大小和哈希，转为正式文件，最后提交数据库记录。任一步骤失败则回滚记录并清理本次 UUID 目录，不改变源文件。每个版本都是独立材料记录，不合并或覆盖旧版。元数据编辑不可改动所属项目或副本路径。

`MaterialService.prepare_preview` 先核对受管理副本存在性、大小和 SHA-256，复制到资料根目录独立 `preview_cache/<UUID>/<原文件名>`，再核对预览字节。每次预览隔离保存，不向编辑器传递 `materials/` 原路径；目录入口同样创建并打开预览目录。耗时复制和哈希由后台任务执行，成功回调在主线程调用 `QDesktopServices.openUrl`。活跃和归档材料采用相同路径，原记录无需写入；打开失败不显示成功。

已交给外部程序的预览文件不自动删除，也不终止编辑器。预览修改需另存后作为新版本导入。备份、导出保护及交付排除该缓存。归档原副本损坏时仅报告事实和恢复条件，不更新旧哈希、静默替换旧版本或声称哈希能还原内容。

## 导出与备份恢复

CSV 使用 UTF-8 BOM；公式开头文本加保护前缀，只改变导出值，不修改原记录。HTML 使用转义，包含项目简介、任务、成果与材料目录，不凭空生成成绩或申请资料。

备份共享写锁，SQLite backup API 建立一致数据库快照，再连同受管理材料及配置打包。manifest 包含格式版本、schema 版本、文件大小和 SHA-256。只打包受支持的必需文件和数据库引用的材料，不递归打包导出、日志、锁文件或其他备份。

Reviewed 不更改备份格式或 schema 版本，预览缓存不在必需文件清单内；配置在备份和恢复时仍须通过共用字段校验。原 V1.0 生成的有效包按原格式恢复，兼容性有单独实际测试记录。

恢复只接受新建/空目录，先在临时目录检查 ZIP 与 manifest 版本、完整文件清单、大小/哈希、数据库完整性/外键/schema、材料引用及路径。拒绝绝对路径、路径穿越、Windows 盘符、符号链接和不支持内容。验证完成才复制到目标；失败当前资料库保持可用。恢复不会自动切换当前窗口，需用新目录重新启动。
